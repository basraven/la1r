# cert-manager

Automates TLS certificates (Let's Encrypt + internal CA) for Ingresses and
services.

Current version: **v1.21.2** (controller, webhook, cainjector).

## Layout
- `cert-manager.yml` — the upstream release bundle (`cert-manager.yaml` from
  release `v1.21.2`), kept **pristine** except for two local edits:
  - a `# source:` header with the upstream download URL, and
  - the `Namespace` object commented out (`namespace.yml` provides it — a
    duplicate would break the kustomize build).
  Upgrade by re-downloading the new `cert-manager.yaml`, re-commenting the
  Namespace, and updating the `# source:` header.
- `kustomization.yaml` — kustomize patches (not inline edits) add the
  `cert-manager-priority` priorityClass and resource limits to the
  `cert-manager` and `cert-manager-webhook` Deployments, and resources to
  `cert-manager-cainjector`. Keeping these as patches means bundle upgrades are
  a drop-in replacement.
- `cluster-issuer-la1r.yml`, `cluster-issuer-letsencrypt-la1r.yml` —
  ClusterIssuers used by workloads.
- `dns-lexicon-webhook.yml` — ACME DNS-01 webhook (Lexicon) for clusters like
  Pi-hole; the image is pinned **by digest** because upstream only publishes
  `:latest`.
- `namespace.yml`, `priorityclass.yml` — supporting resources.

## Security notes
- Install `pihole`/`dns`/workload secrets out-of-band (the webhook and issuers
  reference them by name only; none are committed).
- The cluster's PKI material (issuer account keys, TLS secrets) lives in
  Kubernetes Secrets generated by cert-manager and is not stored in this repo.

## Apply
```
kubectl apply -k kubernetes/cert-manager/
```

## Check
- `kubectl get certificates -A` — all should be `True` (Ready).
- `kubectl get crds | grep cert-manager`
